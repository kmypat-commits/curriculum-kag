# Локальная обучаемая модель выбора дисциплин

Статус: вариант согласован пользователем; письменный дизайн для проверки до реализации. Не воспроизведение закрытой Jev и не заявление о равной точности.

## Цель и границы

Curriculum-KAG остаётся планировщиком. Новый decision layer обучается выбирать релевантные дисциплины по содержанию и профессиональной задаче, возвращает вероятности и может отказаться от автоматического решения. Нынешний local-content-1.7 — baseline, а не обученная модель. Существующие структурные gates, пререквизиты и требования методиста сохраняются. Этот этап не закрывает нагрузочную приёмку, анимацию и предметную проверку20→40.

## Выбранный подход

Локальный компактный классификатор на замороженных существующих embeddings курса и профиля, их взаимодействиях и признаках достаточности источников. Первая модель — регуляризованная multinomial logistic regression с отдельно обученной калибровкой; nonlinear MLP рассматривается только если сравнение выявит необходимость. Это обучаемый специализированный слой, не обучение универсальной модели с нуля. Внешний Jev допустим только как поздний отдельный benchmark после согласования API/передачи данных; не runtime dependency.

## Вход и выход

Вход: programme/profile hash; цель и РО; block definition и подтверждённые требования; course content hash; immutable source/chunk references; embedding model/version/dimension; фактический перечень допустимых кандидатов. ID курсов и название университета не являются predictive features.

Первое атомарное решение — роль курса относительно указанного профессионального блока: professional/supporting/unrelated. Regulatory определяется существующей нормативной политикой, не предсказывается. Выход: распределение этих ролей, action prefer/retain/deprioritise/review, reason codes, ссылки на реальные входные фрагменты, model/dataset/calibration versions и input hashes. Недостаточные/устаревшие/несовместимые данные возвращают review, без выдуманного confidence. Модель не генерирует доказательства: фрагмент является проверяемым источником, а не доказательством причинности предсказания.

Низкоуверенное решение не удаляет курс из frontier; оставляет baseline и предупреждение. prefer/deprioritise меняют только bounded soft utility. retain сохраняет baseline. Совместная оптимизация MILP выбирает допустимое расписание; выход модели не заменяет оптимизатор. Уверенность калибруется на отдельной выборке, не берётся из embedding cosine.

## Разметка и защита от утечки

Dataset record: профиль/блок, курс/контент, роль, sufficient/insufficient, reviewer identity, timestamp, источник, content hashes и comment. AI proposals хранятся отдельно и не являются gold. MatchFeedback может предложить примеры, но confirmed LO match не превращается автоматически в professional-role label. Неоднозначные примеры размечаются вторым предметным reviewer; disagreement остаётся review, не majority fiction.

Train/calibration/test split группируется по происхождению программы и semantic course family; одинаковые/скопированные описания не пересекают splits. Не использовать20→40 как training labels и затем заявлять их независимым тестом. Фиксировать split manifest и SHA256 до обучения. Negative cases включают чужие отрасли, generic management, похожую лексику, разные языки/уровни, скопированные описания и недостаточное содержание.

## Проверки и rollout

Сначала shadow: решения по сохранённым входам без изменения планов. Сравнение baseline и learned layer: macro-F1 ролей, confusion matrix, Brier score/ECE, selective risk/coverage, число необоснованных professional решений, abstentions, latency/memory. При малом тесте — доверительные интервалы и запрет широкого вывода о качестве.

Предложенный release gate для influence: не менее100 вручную проверенных test examples из минимум5 непересекающихся programme groups; threshold выбирается только на calibration. На test среди автоматических professional решений нижняя95% граница precision не менее0.90, не менее30 таких решений; иначе shadow/review. Эти пороги — проверяемое предложение дизайна, не выполненные результаты. Публиковать coverage, чтобы отказами нельзя было скрыть слабую модель.

Сравнение вариантов на одинаковом frozen catalogue: профильные/посторонние дисциплины, meaningful duplicates, подтверждённые блоки, structural success, время и peak RSS. После исправлений все те же20 с начала, независимые identity/file+canonical hashes/credits/load/prerequisites/required и предметная оценка; лишь затем40. Если модель не достигает gate, генерация работает baseline без ложного статуса готовности.

## Хранение и безопасность

Artifact содержит model weights, encoder identity, feature schema, calibration, training/split manifest, metrics и checksums; загрузка только доверенных локальных артефактов без небезопасного произвольного pickle. Cache key включает профиль/блок/курс hashes и все версии. Ручное изменение инвалидирует соответствующую оценку. Project ownership применяется к API и журналу; ни данные другого проекта, ни внешние сетевые запросы не допустимы.

Influence flag отделён от shadow flag, rollback возвращает baseline без удаления опубликованного плана. Недоступный артефакт не ломает нормативную генерацию. Никакого автоматического удаления legacy prerequisite edges: отдельная модель review relations может появиться позже, но изменение графа требует предметного решения и snapshot-backed миграции.

## Поэтапность

1. Контракт/fixtures и dataset exporter с provenance; разметка методистами.
2. Группированные splits, baseline training, calibration и воспроизводимый report.
3. Shadow adapter поверх существующих content_evaluation services.
4. После release gate — bounded utility integration и журнал действий.
5. Сравнение20→40, нагрузочные замеры; анимация показывает реальные решения/события.

До согласования письменного дизайна продуктовыйкод/обучение нового decision layer не начинать. Реализационный план создаётся после проверки этого документа.
