# TEM: повтор фиксированной выборки после исправлений

## Исходный результат

`tem-real-80-v2-loadfix` завершён: 19/80 прошли внутренний gate, 61/80 не прошли.
Отдельная проверка структуры: 72/80 без выявленных структурных нарушений.
Это не независимая экспертная оценка применимости программ.

## Подтверждённые причины

1. `variant_lo_repair` использовал усиленный поисковый `MatchScore.score` для покрытия LO,
   тогда как verifier использует исходный semantic/expert score. При насыщении рейтинга
   до 1.0 замена слабой дисциплины не запускалась. Исправлены расчёт покрытия,
   оценка кандидатов и сохранение LO-evidence при доменных заменах.
2. Клинический маркер `уролог` совпадал с серединой слова `культурологической`.
   Verifier ошибочно назначал клинический минимум семестра. Добавлены границы слов
   и регрессионные тесты для культурологии и настоящих клинических дисциплин.
3. Импорт кандидатов применял LIMIT без ORDER BY. Зафиксирован порядок ID до LIMIT,
   а также порядок разрешения одинаковых названий существующего каталога.

Контрольный повтор программы 10251 после исправления LO-evidence: hard=0,
но общий quality gate всё ещё false (минимальное покрытие 0.509 при требовании 0.6
и два замечания к семестрам). Этот повтор предшествовал исправлению клинического
маркера и стабилизации порядка выборки; его нельзя считать финальным результатом.

## Новый прогон

Префикс: `.runtime/tem-real-80-v2-evidencefix`.
Используется прежний `real-cohort-inputs-v2/manifest.json`: 50 + 30 непересекающихся программ.
Старые отчёты не перезаписываются. Хэш кода охватывает теперь весь backend/app
и исполняемые скрипты аудита/координатора. Диагностика показывает semantic_score отдельно от rank.
Порог качества, требования к кредитам и состав входных программ не ослаблены.

Ограничение сравнения: общий каталог пополняется при импорте EPVO; прежний прогон
не сохранял полную копию состояния БД. Одинаковые входы не означают побитово одинаковую
базу кандидатов. Изменение процента прохождения нельзя приписывать только одному исправлению.
