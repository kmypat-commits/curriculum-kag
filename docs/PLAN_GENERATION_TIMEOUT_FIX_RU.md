# Исправление долгой генерации новых ОП

Проблема воспроизведена на программе AgroTech, версия 13.

Причины:

1. Нехватки RAM не было: backend использовал около 0,3 ГБ.
2. Узкий EPVO-scope ошибочно запускал полную переиндексацию всего репозитория перед LO1.
3. Во время генерации удалялись старые проекты, из-за чего SQLite возвращал `database is locked`.
4. Одинаковые тексты дисциплин повторно кодировались для каждого LO.

Исправления:

- large-catalog режим определяется размером всего репозитория;
- полная переиндексация больше не запускается при каждой новой программе;
- добавлен LRU-кэш до 8192 эмбеддингов;
- SQLite переведён в WAL;
- `busy_timeout` увеличен до 120 секунд;
- удаление проектов блокируется с понятной ошибкой, пока строится план;
- progress status содержит `updated_at`.

Проверка:

- 9 LO рассчитаны;
- создано 720 связей дисциплина–LO;
- A/B/C сформированы примерно за 1,5 минуты;
- каждый вариант содержит 240 кредитов;
- жёстких нарушений: 0;
- старые планы не удаляются до успешного завершения всех новых вариантов.
