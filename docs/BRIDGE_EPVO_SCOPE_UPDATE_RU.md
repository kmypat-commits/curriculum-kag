# Bridge-замены и направления ЕПВО

Обновление:

- В preview замены bridge у каждого сильного кандидата появилась кнопка «Добавить в проект».
- Backend проверяет, что дисциплина:
  - относится к ЕПВО;
  - находится в разрешённом направлении/группе проекта;
  - ещё отсутствует в плане;
  - имеет `EPVO >= 50%` или `AI >= 65%`.
- После подтверждения bridge заменяется реальной дисциплиной. Пользователю предлагается перестроить A/B/C для полного пересчёта метрик.
- Связи дисциплина–LO ниже 40% больше не показываются как подтверждённые.
- Связи с экспертным вердиктом `incorrect` исключаются из:
  - блока «Почему выбрана?»;
  - результатов обучения семестра.
- Выбор направлений и групп ЕПВО перенесён в первый шаг создания программы.
- Названия выбранных направлений автоматически становятся областями программы.
- Репозиторий дисциплин получил фильтры по направлению подготовки и группе ОП вместо основного фильтра по свободной предметной области.
- Фильтр репозитория оптимизирован:
  - исключён полный JSON-scan 191 тыс. нормализованных дисциплин;
  - повторный запрос по направлению 6B101 сократился примерно до 1,4 секунды.
- Bridge replacement получил domain/content guard:
  - «Основы медицины» ищет кандидатов только во втором медицинском направлении;
  - общеобразовательные и чисто IT-дисциплины исключаются;
  - для программы «Айти медицина» вместо алгоритмов теперь предлагаются клинические/патофизиологические модули ЕПВО.

Проверка:

- backend compile: OK;
- регистрация нового route: OK;
- frontend production build: OK;
- live API: OK через локальную SQLite fallback;
- backend/frontend health: OK;
- проверены программы IT медицина (8) и Айти медицина (12);
- endpoint применения замены корректно валидирует входные данные.
