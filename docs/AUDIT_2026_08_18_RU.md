## Что ещё не закрыто

### 1. Междисциплинарная квота

Контрольная программа «IT + Здравоохранение» (бакалавриат, ГОСО РК, 240 кредитов) получила 240/240 кредитов, 0 ошибок семестров и пререквизитов, ГОСО проходит, но вторичная квота 40% пока даёт 57,7 из требуемых 68 кредитов (допуск 3). Это единственный подтверждённый дефект качества последнего прогона. Генератор корректно не подделывает результат bridge-модулями.

В алгоритм добавлено языко-независимое сопоставление явных доменов (`Medicine`/`Healthcare`/`Здравоохранение`, а также сельское хозяйство и ИКТ). Следующий технический шаг — расширить квотный кандидатный пул из нормализованного EPVO-репозитория, сохраняя LO-доказательство и уровень образования, а не снижать квоту.

### 2. Размер модулей

`course_selection.py` уже является фасадом (14 строк). Остались крупные файлы:

- `variant_strategy.py` — 2253 строки;
- `semester_repair.py` — 1261 строка;
- `planner_replacements.py` — 1123 строки;
- `PlanBuilder.jsx` — 1316 строк.

Их безопасное разбиение ещё не завершено; функциональность сначала фиксируется интеграционными тестами.

### 3. Полный набор независимых контролей

Последний полный контроль после финального изменения выполнен для IT+Здравоохранение. Перед релизным утверждением нужно повторить единый скрипт для стандартной, междисциплинарной, международной, магистерской и докторской программ и сохранить JSON-отчёты в `.runtime/fresh-controls`.

Свежие контрольные прогоны 18.08.2026:

- бакалавриат ГОСО РК: 240/240, hard-нарушения 0, качество пройдено;
- магистратура ГОСО РК: 120/120, hard-нарушения 0, качество пройдено;
- докторантура ГОСО РК: 180/180, hard-нарушения 0, качество пройдено после переноса исследовательской практики на следующий семестр и балансировки раннего курса;
- IT + медицина: качество требует отдельного завершения квотного retrieval (вторичная квота является активным дефектом);
- IT + агрономия: повторный полный прогон после исправления распознавания компетенций дал 240/240, 0 нарушений кредитов/семестров/пререквизитов, квоты 104,5/65,5 и 4 bridge-модуля; `quality_passed=true`, ГОСО проходит.

## План следующих этапов

1. **Квотный пул EPVO** — добавить bounded retrieval из нормализованного репозитория для недостающей области; учитывать уровень `6B/7M/8D`, экспертный балл и минимум одно профессиональное LO-доказательство.
2. **Повторный контроль** — пять профилей × нужные юрисдикции; фиксировать кредиты, LO, ГОСО, домены, bridge, семестры и пререквизиты.
3. **Рефакторинг planner** — вынести из `variant_strategy.py` retrieval/ranking/assembly; из `semester_repair.py` load/prerequisite/appropriateness; сохранить публичные фасады.
4. **Интеграционные тесты** — отдельные PG-контракты для build, graph, coverage, replacements и syllabus; запускать в CI с Postgres service.
5. **UI** — разделить `PlanBuilder` на quality, bridge replacements и LO coverage panels; проверить graph и три языка через smoke-тесты.
6. **Производительность** — не повторять EPVO/LO-индексацию при неизменном checksum; вынести progress генерации в PostgreSQL; собрать p50/p95 для страниц и генерации.
7. **Релиз** — backup, миграции Alembic, lock-файлы зависимостей, model/data manifest, Git tag и инструкция развёртывания.

## Новый аудит объёма проекта

Измерение 18.08.2026 показывает: `backend/models` ≈ 49,6 GB, `backend/.runtime` ≈ 6,3 GB, `backend/venv` ≈ 4,9 GB, `backups` ≈ 17,4 GB. Это не дефект приложения, но эти каталоги нельзя включать в Git или контейнер релиза целиком. Модели и резервные копии должны поставляться отдельными артефактами с manifest/checksum; `venv` и кэши — пересоздаваться из lock-файлов.

Текущий аудит подтверждает работоспособность тестового и production-build контура. Не закрыты миграция Alembic, полный PG endpoint smoke-тест на отдельной `_test` базе, квота IT+медицина и разбиение крупных UI/planner-модулей. Поэтому система готова к контролируемому staging, но ещё не к безусловному production-релизу.

## Ограничения аудита

Снижение квоты или признание bridge реальной дисциплиной не допускается: это улучшило бы цифру, но исказило бы качество. Порог «90–100%» можно заявлять только после независимого прогона с сохранёнными отчётами и экспертной верификацией.
