# Production runbook

Продакшен-шаблон использует PostgreSQL/pgvector на `5433` и backend без `--reload`.

1. Скопируйте `.env.production.example` в `.env.production` и замените все тестовые значения. Заполненный файл не коммитить.
2. Укажите `DATABASE_URL` с host `postgres`; если пароль содержит `@`, `#`, `/` или `:`, предварительно URL-encode эти символы. Compose намеренно не собирает URL из сырого пароля.
3. Запустите `docker compose --env-file .env.production -f docker-compose.production.yml up -d --build`.
4. Caddy автоматически получает HTTPS-сертификат для `DOMAIN`, если DNS уже указывает на сервер. Проверьте `https://DOMAIN/api/health` и статус `docker compose ... ps`.
5. Делайте резервную копию: `powershell -File .\scripts\backup-postgres-production.ps1`. Скрипт сохраняет бинарный custom-format dump напрямую, без PowerShell pipeline.
6. Храните копии вне хоста и периодически проверяйте восстановление на отдельной shadow-базе.
7. Для миграционной приёмки используйте отдельную пустую БД и reviewed orphan manifest: `python backend/scripts/accept_sqlite_postgres_migration.py --target postgresql+psycopg2://... --orphan-manifest .runtime/sqlite-fk-discard-manifest-2026-09-03.json --output .runtime/migration-acceptance.json --restore`. Скрипт отклоняет непустую target DB, сверяет counts/FK/full-row SHA-256 и выполняет изолированное восстановление backup.
8. Для retention telemetry сначала выполните dry-run: `python backend/scripts/purge_audit_telemetry.py --retention-days 365`. Удаление допускается только явным `--apply`; скрипт затрагивает только `planner_build_telemetry`, а security audit events не удаляет. Запускайте по расписанию после проверки backup.
9. Для однократной проверки p95 без постоянного polling задайте токен в окружении текущего процесса и используйте `powershell -File .\scripts\monitor-planner-performance.ps1 -ProjectVersionId <id> -RequireSample`: `$env:CURRICULUM_PLANNER_MONITOR_TOKEN = '<token>'`. Не передавайте токен аргументом командной строки, чтобы он не попал в список процессов. Код `1` означает превышение budget/отсутствие samples, код `2` — недоступность API; скрипт можно подключить к Task Scheduler или внешнему alerting.
10. Свежесть backup проверяйте командой `powershell -File .\scripts\monitor-backup-age.ps1 -MaxAgeHours 26 -VerifyChecksum`. Код `1` означает устаревший/некорректный backup, код `2` — отсутствует каталог; подключайте после backup к Task Scheduler или внешнему alerting.
11. Единый staging-gate запускайте после старта сервисов: `powershell -File .\scripts\monitor-staging-observability.ps1 -CheckDocker -ProjectVersionId <id> -RequirePlannerSample -BackupDir .\backups\postgres-production -VerifyChecksum`. Он однократно проверяет health/Docker, p95 и backup; частый polling не используется.
12. Для aggregate-alerts планировщика задайте токен только в окружении процесса и добавьте `-CheckPlannerObservability`: `$env:CURRICULUM_PLANNER_MONITOR_TOKEN = '<token>'; powershell -File .\scripts\monitor-staging-observability.ps1 -CheckPlannerObservability -MaxFailedOrTimedOut 0 -MaxActiveLeases 0`. Gate завершится с кодом `1` при failed/timed-out builds, активном lease или превышении p95; токен не передаётся аргументом командной строки.

Перед repair Docker ознакомьтесь с [инструкцией восстановления runtime](DOCKER_RUNTIME_RECOVERY_RU.md) и запускайте его из интерактивного окна: `powershell -File .\scripts\repair-docker-runtime.ps1 -NoStart`; UAC должен быть видимым и подтверждён вручную. Скрипт не изменяет VHDX/volumes и завершится с timeout, если UAC не подтверждён. Локальная проверка маршрутов: `powershell -File .\scripts\ui-smoke.ps1`. Она проверяет основные страницы, включая `/projects/13/graph`, UTF-8 HTML и наличие RU/KK/EN подписей. После запуска frontend выполните браузерный smoke-чек-лист: открыть план → граф, переключить RU/KK/EN, проверить названия дисциплин/циклов/доменов и нажать «Повторить загрузку графа» при ошибке. Если `localhost:3001` не отвечает, это инфраструктурный блокер smoke, а не доказательство дефекта графа.

Проверка доступности для планировщика: `powershell -File .\scripts\monitor-health.ps1`. Для staging добавьте bounded-проверку Docker engine: `powershell -File .\scripts\monitor-health.ps1 -CheckDocker`. При сбое команда возвращает код `1`, поэтому её можно подключить к Task Scheduler, cron или внешнему мониторингу. UI опрашивает долгую генерацию с интервалом 30 секунд, а после сетевой ошибки повторяет через 60 секунд; частый polling не используется.

Ограничение: внешний домен, TLS, WAF и мониторинг (Sentry/Prometheus) зависят от выбранного сервера и пока не включены автоматически. Перед публикацией добавьте reverse proxy с HTTPS и секретное хранилище.
