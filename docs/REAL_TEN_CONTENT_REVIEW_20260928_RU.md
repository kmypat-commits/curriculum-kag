## Системные приоритеты

1. **Профильное ядро до подбора.** Предлагать блоки из квалификации, цели и РО; методист подтверждает обязательность. Широкое совпадение домена допускает кандидата, но не доказывает покрытие блока. Деревообработка и робототехника — обязательные содержательные контрольные примеры.
2. **Эквивалентность по содержанию.** Нормализовать названия для поиска кандидатов, затем учитывать описания, РО, уровень и язык. Защищать разные уровни, minor, курсовые работы и самостоятельные компоненты. Ограничение выбора должно действовать внутри solver, не удалять курсы после формирования кредитов.
3. **Последовательность с доказательствами.** Отличать подтверждённые prerequisites от рекомендуемого порядка «основы → методы → приложение». Нулевые сохранённые связи не означают хороший порядок. Не добавлять жёсткие зависимости только по словам названия.
4. **Объяснимые включения и пробелы.** На выходе показать блок, источник evidence, поддержанные РО, причину семестра и спорные межпрофильные включения. Это помогает университету доработать базу и сформировать обоснованный промпт для внешней LLM.
5. **Приёмка содержания.** Помимо credits/load/prerequisites фиксировать покрытие подтверждённого ядра и списки потенциальных перекрытий. Не выдавать семантический score за академическое одобрение. Не обещать 100% валидных планов для объективно несовместимых требований.
