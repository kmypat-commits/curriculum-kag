Статус: **входные брифы, не сгенерированные учебные планы**. Исполнять по `03_ACCEPTANCE_PROTOCOL_RU.md`, после исправления влияющих P1. Не подменять цели и LO стандартными шаблонами. Точные коды ЕПВО разрешает исполнитель через текущий каталог и фиксирует до запуска. Если область не поддержана, фиксировать пробел, а не переносить её в ICT.

Объёмы ниже соответствуют профилям, присутствующим в приложении; применимость конкретной программе проверяет методист. Каждый кейс запрашивает A/B/C. Общие обязательные нормативные компоненты добавляются отдельно, не заменяя профессиональные LO. «Не принимать» — содержательный контрпример, а не предложение добавить хардкод по названию программы.

## P01. Информационные системы здравоохранения

Профиль: bachelor, обычная траектория, KZ, 240 кредитов / 8 семестров; язык RU. Междисциплинарная: ICT + здравоохранение. Максимум новых модулей: 3.

LO1. Моделировать маршрут пациента и требования к информационной системе, создавая согласованную процессную модель и спецификацию данных.

LO2. Реализовывать обмен медицинскими данными и проверять корректность их структуры и терминологии на тестовом стенде.

LO3. Проектировать хранение, разграничение доступа и аудит действий с медицинскими данными на основе модели угроз.

LO4. Оценивать качество данных и диагностировать ошибки медицинской аналитики на размеченном учебном наборе.

LO5. Разрабатывать и испытывать прототип рабочего места медицинского пользователя с измеримыми критериями удобства и безопасности.

Обязательные блоки: клинические процессы/терминология; программирование; БД; интеграция; приватность; качество данных; человекоориентированное проектирование; проект с профильной практикой.

Ожидаемая цепочка: БД → медицинская модель данных → интеграция → проект; основы статистики → медицинская аналитика.

Не принимать: план только из общего IT; клиническую диагностику как полномочие ICT-выпускника; ecology/safety как обязательную основу cybersecurity; bridge, заявляющий все LO без содержания.
