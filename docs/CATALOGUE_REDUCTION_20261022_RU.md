# Возврат рабочего каталога к сентябрьскому составу

Пользователь выбрал исторический состав SQLite snapshot от 11 сентября:
20 782 дисциплины. Текущие тексты и переводы сохраняются, старые значения
карточек из SQLite поверх них не накладываются.

План: из 57 392 карточек сохранить 21 495, архивировать 35 897 поздних EPVO
добавлений. Сохраняются коды из исторического снимка, все не-EPVO карточки,
ссылки планов/ручного feedback/черновиков/baseline/силлабусов и замыкание
обязательных пререквизитов. Равенство названий не используется для удаления.

Архив пользователя на внешнем диске:
`E:\curriculum-kag-archive\20261022-before-catalog-reduction`.
Там сохраняются workspace, полный PostgreSQL dump с SHA256, точный план с IDs,
отчёт применения и отдельный dump архивной схемы. Исходный frozen manifest
и прежние translation snapshots не изменяются.

Архивирование переносит точные строки в отдельную PostgreSQL schema:
courses, course_chunks, course_localizations, embeddings, match_scores,
course_prerequisites, graph_edges, epvo_disciplines_normalized. Связи approval
архивируемых курсов снимаются только после копирования исходных строк.
Исходный слой EPVO сохраняется. Транзакция блокируется при активных jobs или
изменении проверенного плана; hashes пользовательских таблиц проверяются
до commit и повторно после него. Новые schema создаются без перезаписи.

Первый перенос безопасно отменён на cascade delete: в legacy public schema
отсутствовали referencing-side индексы course_chunks/course_id и ряда других
FK. Rollback подтверждён: courses=57392, архивная схема не создана. Повторный
вариант создаёт временные индексы в той же транзакции и удаляет их после
проверок. Интеграционный тест PostgreSQL повторно подтвердил rollback,
восстановление и отсутствие оставшихся maintenance indexes.

Причина роста исправлена: approve_epvo_candidates по умолчанию только связывает
существующие курсы. Добавление карточек требует явного импорта. Контрольный CLI
дополнительно ставит session-level before_flush guard против создания Course
другими путями, включая ГОСО. Недостающая карточка даёт честный отказ вместо
расширения общей БД. Версия EPVO stage cache обновлена.

Проверки: RED воспроизвёл автоматическое создание курса; GREEN подтвердил
нулевой рост и использование существующего курса. Отдельный guard не мешает
обычному ручному созданию после выхода из control scope. PostgreSQL integration
на отдельной временной БД проверил архивирование, защиту reviewed translation,
FK/cascade, rollback DDL/данных при ошибке, восстановление и отказ повторного
восстановления поверх существующих IDs. Тестовая БД удалена после проверки.
Полный backend pytest прошёл exit0; opt-in/dependency warnings сохранены в
`.runtime/catalogue-reduction-tests-green-20261022.log`.

Точечное восстановление архивированных строк при отсутствии конфликтов:

```powershell
backend/venv/Scripts/python.exe backend/scripts/archive_catalogue_to_snapshot.py --restore --archive-dir E:/curriculum-kag-archive/20261022-before-catalog-reduction
```

Команда восстановления не запускалась в рабочей БД. При конфликте Course IDs,
кодов или переназначенных EPVO mappings она отменяет транзакцию. Полный dump
служит отдельной точкой восстановления всей БД до сокращения.
