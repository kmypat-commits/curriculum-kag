## Фаза 2. Прод-таргет: Supabase + хостинг бэкенда

**Vercel не подходит для полного стека** (Python+torch/SBERT, 11 GB БД, subprocess-обучение, git-shell вызовы). Честная конфигурация:

- **Supabase = да** — управляемый Postgres 16 + pgvector + auth + storage. Это целевой слой данных и заодно закрывает путаницу 5432/5433 (локальный primary/shadow).
  - Миграция уже возможна: `pg_dump` (backup verified) → импорт в Supabase.
  - Векторы: `pgvector` уже используется (`HAS_PGVECTOR`).
  - Auth: сейчас JWT + OAuth2PasswordRequestForm — при желании переносится на Supabase auth.
- **Backend**: Render / Railway / Fly.io (Docker, `backend/Dockerfile` уже есть) — долгоживущий Python-процесс, подходит. Либо остаётся локальным Docker для исследовательских задач.
- **Frontend**: Vercel/Netlify — только статический демо-слой, при условии выноса тяжёлых операций в API бэкенда.
