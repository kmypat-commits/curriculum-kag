# Политика хранения ML-моделей Curriculum-KAG

## Фактическое состояние

Локальный `backend/models` занимает около 50 ГБ. Для рабочего приложения используется один подтверждённый кандидат:

```text
backend/models/epvo-sbert-finetuned-40k
```

Он самодостаточен: содержит `model.safetensors` (~1,061 МБ), tokenizer, config и pooling-конфигурацию. Каталог базовой модели не требуется для обычного inference этой сохранённой модели.

## Классы хранения

### KEEP — до публикации обязательно

- `epvo-sbert-finetuned-40k`;
- frozen metrics и Dataset Passport;
- split/checksum/seed/config, использованные в статье;
- скрипт обучения и точные requirements.

### ARCHIVE — сохранить вне рабочего проекта

- все каталоги `*-checkpoints`;
- пилотные hard-negative, ranking-loss, cached-ranker, multipositive и weighted модели;
- базовый `paraphrase-multilingual-mpnet-base-v2`, если требуется полностью офлайн-воспроизводимое обучение.

Для статьи достаточно сохранить компактные `metrics.json`, manifests и README каждого эксперимента. Полные веса нужны только для тех вариантов, которые предполагается независимо повторно проверить.

### REMOVE — только после проверки архива

- незавершённые checkpoint-каталоги без метрик;
- дубли весов с одинаковым SHA-256;
- временные smoke-модели;
- кэши скачивания, которые воспроизводимо восстанавливаются из публичного источника.

## Безопасный порядок

1. Загрузить production-модель в отдельный Hugging Face Model repository.
2. Скачать её в чистый каталог и выполнить encode smoke-test.
3. Сверить SHA-256 и frozen benchmark.
4. Архивировать научно значимые экспериментальные веса во внешнее хранилище.
5. Только после этого удалять локальные дубли.

До выполнения шагов 1–4 автоматическое удаление запрещено.
