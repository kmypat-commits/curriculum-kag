### Совместимость векторов: проверка исходного контракта

Текущий _course_match_text включает название, описание, переводы описания, темы и РО; candidate_texts обрезает результат до3000 символов. index_course, напротив, кодирует каждый description/topics/learning_outcomes chunk отдельно. Поэтому векторы этих путей не взаимозаменяемы даже при одинаковой модели. Старый index_course удаляет все CourseChunk курса перед созданием новых; его нельзя использовать как безобидное пополнение кеша, поскольку это меняет идентичность фрагментов и может затронуть существующее evidence. Диагностика его не запускала.

encode_batch имеет ограниченный in-memory LRU и при недоступности SentenceTransformer возвращается к encode; get_model_version сообщает feature-hash-v2, если модель не загружена. Новый контракт обязан различать наученный семантический encoder и лексический hash fallback: одинаковый размер/косинус не делает fallback семантическим подтверждением. Ключ кеша должен включать фактический encoder, версию построения текста и hash самого текста; расчёт отсутствующих векторов не должен удалять CourseChunk/MatchScore или изменять дисциплины. Это уточнение предложенного дизайна, не реализованная функция. Требуется согласование перед TDD и нагрузочными вычислениями.

### Отображение ограничений проверки

Source inspection frontend/src/components/ContentEvaluationPanel.jsx: предупреждение о предполагаемой эквивалентности выводит только course_ids. Причина, similarity, embedding_model и embedding_findings пользователю не показываются; отдельного счётчика semantic/lexical/unavailable нет. Общая advisory-оговорка присутствует в translations.js, поэтому интерфейс не объявляет академическую готовность прямо, однако не раскрывает обнаруженный пробел покрытия. Это source-level наблюдение, не новая browser QA. В согласуемом исправлении нужны раздельные показатели технического покрытия и модели evidence, а не единый процент качества. Предупреждение должно показывать названия, причину, источник/фрагменты и тип encoder; unavailable не должен выглядеть как отсутствие повторов. API старых отчётов без этих полей должен отображать «покрытие проверки неизвестно», не ноль. Код интерфейса не менялся.

Read-only SQL с vector_dims по выбранным уникальным нерегуляторным курсам: все105 description embeddings имеют model_version=feature-hash-v2 и размерность768. Таким образом, ранее141 вхождение с вектором — лишь техническое наличие, а не141 семантически проверенное вхождение. Для принятия содержательной проверки требуется честный режим lexical/semantic/unavailable с evidence фактического encoder; ни ноль предупреждений, ни наличные hash embeddings такой приёмки не дают.
