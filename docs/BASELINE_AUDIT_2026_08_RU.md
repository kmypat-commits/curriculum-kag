## Найденные риски

1. Большие каталоги находятся рядом с кодом и требуют политики хранения, но удалять их без архива нельзя.
2. Есть несколько файлов зависимостей с различающимися версиями; Docker и локальная среда могут собираться по-разному.
3. Alembic присутствует, но полноценная история миграций требует отдельной подготовки.
4. Возможен автоматический fallback с PostgreSQL на SQLite.
5. Рефакторинг `scheduler.py` и `planner.py` требует тестов до разделения файлов.
6. Перед GitHub необходим secret-scan и проверка `.env`/истории Git.

## Исправление локализации (2026-08-01)

Исправлена причина неполного переключения языка в плане: пререквизиты и часть EPVO-дисциплин использовали только `Course.title`. Теперь API обогащает единую карту локализации полями `title_ru/title_kk/title_en` из нормализованного EPVO, а UI использует эту карту для названий пререквизитов и постреквизитов. Если подтверждённого перевода нет, показывается явный fallback, а не пустое название.

Дополнительно унифицирован код казахского языка `kk` (старый alias `kz` принимается только на backend), исправлены прямые ветвления UI по `kz`, а построение списка следующих дисциплин в графе переведено на пакетно загруженную карту локализации без дополнительных SQL-запросов на каждую дисциплину.

Первичный поиск по шаблонам ключей дал совпадения в конфигурационных примерах, документации и коде. Значения секретов в отчёт не выводились; требуется ручная проверка `.env` и истории Git перед публикацией.
