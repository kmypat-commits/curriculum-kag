# Архитектура публичного релиза Curriculum-KAG

## Название экспертного набора

Публичное исследовательское название — **Curriculum Expert Evidence Repository (CEER)**, или «Репозиторий экспертных данных для проектирования образовательных программ».

CEER — это не переименование источника задним числом. В научном описании сохраняются происхождение, идентификатор исходной записи, дата извлечения, версия нормализации и checksum. Нейтральное имя обозначает созданный исследовательский слой и исключает впечатление, что государственная платформа является владельцем или оператором Curriculum-KAG.

## Разделение поставки

```text
GitHub: curriculum-kag
  код, Docker, миграции, тесты, документация

Hugging Face Model: curriculum-kag-ceer-sbert-40k
  production-веса, tokenizer/config, Model Card, checksums

Hugging Face Dataset: curriculum-expert-evidence-repository
  только разрешённые CEER-таблицы, Dataset Card, passport

Hugging Face Space: curriculum-kag-demo
  Docker-демо на обезличенных данных

Institutional PostgreSQL
  пользователи, проекты, обратная связь и локальные данные вуза
```

## Почему база публикуется отдельно

База изменяется, имеет отдельные права распространения и значительно тяжелее исходного кода. GitHub должен оставаться быстрым инженерным репозиторием. Dataset Hub обеспечивает версионирование и streaming статических исследовательских таблиц, а PostgreSQL остаётся рабочим хранилищем конкретной установки.

## Профили установки

- `demo`: небольшая разрешённая выборка и CPU/fallback, знакомство с интерфейсом;
- `research`: CEER release + production SBERT, воспроизводимые эксперименты;
- `institution`: собственная PostgreSQL, авторизация, резервное копирование и локальные данные;
- `developer`: тестовые данные, hot reload и диагностические инструменты.

## Правило совместимости

Каждый релиз приложения фиксирует минимальные версии `schema_version`, `dataset_version` и `model_version`. Загрузчик обязан проверить SHA-256 и отказать при несовместимой схеме, а не запускать систему с частично подходящими данными.

Реестр прогресса генерации хранится в PostgreSQL (`plan_build_status`). Перед
построением используется блокировка строки версии, поэтому несколько API-workers
не могут параллельно запустить одну и ту же генерацию. До нагрузочного теста
рекомендуется один worker: это консервативный профиль для локального компьютера,
а не ограничение архитектуры.
