## 21992: допустимость и оптимальность — разные условия

Ранее solver отбрасывал любой status=1 даже с найденным допустимым решением.
Теперь status=0/1 с incumbent проверяется на размерность, конечность,
целочисленность, бинарные границы и ВСЕ строки линейных ограничений после
округления. Затем остаются admission, verifier и финальный boundary.
Status=1 без решения не принимается. Оптимальность честно отражается
`optimality_proven=false`, `solver_status=feasible_at_limit`.

Предлагается разделить источник/достоверность связей: подтверждённые остаются
обязательными; подозрительные legacy-связи проходят отдельную проверку и
только явно одобренные ошибочные связи переводятся в карантин. Сохранить
полный snapshot и обратную миграцию, журнал решений, причины и ID каждой
