# Эксперимент Recall@10 ≥ 0,90

Дата контрольного прогона: 18.07.2026.

## Зафиксированный baseline

На frozen test из 120 программ и 1249 LO исходный ranking-loss SBERT имеет
Recall@10 около `0,6721`. Ранее опубликованное значение `0,7071` относится к
менее широкой выборке из 80 программ и не используется как основной baseline.

## Аудит выборки

- train: 8568 программ;
- validation: 1815 программ;
- test: 1832 программы;
- пересечение program ID между split: 0;
- повреждённые positive edges: 0;
- медиана кандидатов на один LO: 42 дисциплины;
- медиана релевантных дисциплин: 5;
- у 262 из 1249 LO более десяти релевантных дисциплин;
- математический потолок обычного Recall@10: `0,9206`.

Следовательно, `Recall@10 = 0,90` требует получить примерно 97,8% достижимого
максимума и является очень жёсткой исследовательской целью.

## Эксперимент 1: programme-aware Cross-Encoder

Обучение: 6000 пар из 150 train-программ, 2933 положительные экспертные связи и
3067 наиболее похожих unlinked hard negatives той же программы. Рабочая модель
не заменялась.

Результат на context-варианте frozen test:

| Метрика | Baseline | Cross-Encoder ensemble |
|---|---:|---:|
| Recall@10 | 0,6052 | 0,6088 |
| MRR | 0,6969 | 0,7030 |
| nDCG@10 | 0,5813 | 0,5867 |

Модель отклонена: прирост мал, train loss около 0,693. Длинный контекст цели и
направления ухудшил исходный bi-encoder, а новая бинарная голова не выучила
многоположительную ranking-задачу за один pilot epoch.

## Эксперимент 2: train-only экспертная память ЕПВО

Для канонического названия дисциплины собраны только train-LO, с которыми эта
дисциплина была связана экспертами. Для новой пары использован максимум и
среднее top-3 сходств нового LO с историческими LO. Вес выбран на validation.

| Метрика | Baseline | Expert memory |
|---|---:|---:|
| Recall@10 | 0,6700 | 0,6802 |
| MRR | 0,7906 | 0,7975 |
| nDCG@10 | 0,6654 | 0,6742 |

## Эксперимент 3: память с учётом группы ОП

К общей памяти добавлен отдельный prior `(группа ЕПВО, дисциплина)`. Лучшие веса
на validation: общий prior `0,20`, scoped prior `0,20`. На test историческая
память доступна для 74,3% кандидатных дисциплин, точная групповая память --- для
62,6%.

| Метрика | Baseline | Scoped memory v2 | Изменение |
|---|---:|---:|---:|
| Recall@5 | 0,4898 | 0,5057 | +0,0158 |
| Recall@10 | 0,6700 | **0,6864** | +0,0164 |
| MRR | 0,7906 | **0,8066** | +0,0160 |
| nDCG@10 | 0,6654 | **0,6821** | +0,0167 |
| HitRate@10 | 0,9704 | 0,9696 | -0,0008 |

Scoped memory является лучшим новым кандидатом по Recall/MRR/nDCG, но пока не
внедряется: прирост должен быть подтверждён дополнительным holdout.

## Почему HitRate@10 уже выше 0,90

`HitRate@10 = 0,9696` означает: для 96,96% LO среди первых десяти есть хотя бы
одна экспертно связанная дисциплина. Это соответствует пользовательской задаче
«дать эксперту хороший вариант для выбора».

Обычный Recall@10 отвечает на более строгий вопрос: какую долю **всех**
связанных дисциплин система вернула. Если с LO связаны 22 дисциплины, top-10
физически не может дать Recall выше `10/22`.

## Следующий эксперимент

Следует отказаться от бинарных hard negatives как основной loss-функции и
обучать multi-positive listwise ranker. Для LO `q`, множества кандидатов `C_q`
и всех экспертных положительных дисциплин `P_q`:

\[
L_q=-\frac{1}{|P_q|}\sum_{c\in P_q}
\log\frac{\exp(s(q,c)/T)}{\sum_{d\in C_q}\exp(s(q,d)/T)}.
\]

Такой loss не объявляет другую правильную дисциплину ложным negative и напрямую
обучает поднимать все экспертно связанные дисциплины. Это наиболее обоснованный
следующий путь к raw Recall@10 `0,80+`, после чего можно оценивать достижимость
`0,90`.

## Эксперимент 4: multi-positive listwise SBERT

Запущен безопасный pilot на 1000 группах. Одна группа содержит один LO, все выбранные экспертами положительные дисциплины и внутрипограммные неразмеченные кандидаты. Используется multi-positive listwise loss:

\[
L_q=-\frac{1}{|P_q|}\sum_{c\in P_q}\log\frac{\exp(s(q,c)/T)}{\sum_{d\in C_q}\exp(s(q,d)/T)}.
\]

Главное отличие: другая экспертно правильная дисциплина для того же LO больше не становится ложным negative. После обучения runner автоматически выполняет raw benchmark и benchmark с train-only памятью по группе ЕПВО. Production-модель меняется только после независимого улучшения Recall@10, MRR и nDCG@10.

Артефакты pilot:

- `backend/scripts/finetune_epvo_sbert_multipositive_ranker.py`;
- `backend/scripts/run_epvo_multipositive_experiment.py`;
- `backend/experiment-results/epvo-sbert-multipositive-listwise-pilot/run-status.json`.

### Результат pilot и ансамбля

Pilot улучшил порядок первых релевантных дисциплин (`MRR = 0,8100`), но не превзошёл прежний лучший Recall@10: `0,6850` против `0,6864`. Простое смешивание старого ranker и multi-positive модели также проверено корректно: вес выбирался на validation, frozen test использовался один раз. Validation выбрал вес новой модели `0,05`, однако test Recall@10 составил только `0,6717`; ансамбль отклонён и в production не внедрён.

Чтобы отделить ограничение метода от недообучения малого pilot, запущена контролируемая абляция на 4000 multi-positive группах. Все остальные условия, split и последующие benchmark сохранены.

### Итог абляции 4000 групп

Увеличение объёма снизило train loss с `3,0993` до `2,7579`, но не улучшило независимый ranking: raw Recall@10 `0,6760`, после scoped-memory `0,6841`, MRR `0,8017`, nDCG@10 `0,6784`. Результат хуже прежнего лучшего scoped варианта (`Recall@10 = 0,6864`) и не внедрён.

Практический вывод: дальнейший перебор loss и объёма данных внутри single-vector SBERT прекращён. Для будущего отдельного исследования обоснован следующий класс методов: гибрид dense+sparse+multi-vector, объединение независимых списков RRF и позднее token-level взаимодействие. До отдельного решения о таком benchmark разработка возвращается к корректности и удобству Curriculum-KAG.
