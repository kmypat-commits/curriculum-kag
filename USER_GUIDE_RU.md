# Curriculum-KAG: как пользоваться без технических знаний

## Запуск

1. Дважды щёлкните `start.bat`.
2. Откройте `http://localhost:3001/`, если браузер не открылся сам.
3. Войдите: `admin@curriculum-kag.local` / `admin123`.
4. Для остановки используйте `stop.bat`.

## Выбор классификации ЕПВО

Поля выбираются последовательно: уровень образования → область образования → направление подготовки → группа образовательных программ. Направления и группы автоматически фильтруются. При построении плана система переносит подходящую проектную выборку реальных дисциплин ЕПВО из normalized-слоя в approved repository; исходные raw-карточки с активными дисциплинами не смешиваются.

## Что делает система

Система не пишет учебный план одной командой. Она проходит контролируемую цепочку:

`Курсы → поиск соответствий LO → граф связей → поиск пробелов → bridge-модули → проверенный план`

### 1. Repository

Это библиотека дисциплин. Здесь должны быть названия, кредиты, описания, результаты обучения, темы и пререквизиты.

### 2. Project

Это будущая образовательная программа: два домена, цель, Learning Outcomes, число семестров и кредитов.

### 3. LO Coverage

Система проверяет, какие дисциплины подтверждают каждый LO. Значение ниже 60% считается пробелом.

### 4. Analyze with AI

Это только диагноз и рекомендации. Кнопка не меняет учебный план.

Если написано `needs courses`, следующий шаг — `Generate missing modules`.
Если написано `too vague`, сначала уточните формулировку LO.

### 5. Bridge Modules

Bridge-модуль — проект новой междисциплинарной дисциплины для закрытия пробела.

1. Нажмите `Generate Bridge Modules`.
2. Просмотрите содержание.
3. Нажмите `Promote to Course` только для одобренного модуля.

Promotion добавляет дисциплину в базу знаний, но ещё не меняет существующий план.

### 6. Plan Builder

Нажмите `Generate Variants`. Система заново создаст варианты A/B/C, заменит старые варианты и проверит:

- общее число кредитов;
- нагрузку по семестрам;
- порядок пререквизитов;
- покрытие LO;
- соответствие доменам проекта;
- redundancy (среднюю похожесть дисциплин).

Выберите вариант и нажмите `Activate`.

## Главное правило

`Рекомендация ≠ изменение плана.`

Чтобы рекомендация попала в план, нужно пройти три шага:

1. создать bridge-модуль;
2. подтвердить его через `Promote to Course`;
3. заново выполнить `Generate Variants`.
# Научный эксперимент T6

Для воспроизводимого запуска NSGA-II откройте PowerShell в каталоге `backend` и выполните:

```powershell
.\venv\Scripts\python.exe scripts\run_t6_experiment.py 4 --runs 10 --seed 42
```

CSV и JSON появятся в папке `backend/experiment-results`.

## Автоматическое создание образовательной программы

1. На главной странице нажмите **«Создать проект»**.
2. Введите название программы и две предметные области.
3. Нажмите **«Предложить 3 цели»**. Система сформирует три формулировки с учётом названия и областей. Вариант со звёздочкой считается рекомендуемым.
4. Нажмите **«Выбрать эту цель»**. Цель можно отредактировать вручную.
5. Нажмите **«Далее»**. Кнопка недоступна, пока обязательные поля не заполнены.
6. На шаге результатов обучения нажмите **«Предложить результаты обучения»**.
7. Добавьте результаты по одному кнопкой **«Добавить»** либо нажмите **«Добавить все»**. Любой результат можно исправить или удалить.
8. Задайте количество семестров, кредитов и другие ограничения, проверьте итог и создайте проект.

Помощник не подменяет решение эксперта: он ускоряет подготовку качественного черновика, а пользователь утверждает и при необходимости редактирует формулировки.

## Что выполняют основные кнопки

| Кнопка | Результат |
|---|---|
| **Создать проект** | Открывает пошаговый мастер новой программы. |
| **Предложить 3 цели** | Создаёт три цели по названию и предметным областям; первая отмечается как рекомендуемая. |
| **Выбрать эту цель** | Переносит выбранную формулировку в поле цели. |
| **Предложить результаты обучения** | Формирует шесть измеримых LO: предметные, интеграционные, аналитические, командные и этические. |
| **Добавить / Добавить все** | Переносит предложенные LO в программу без удаления уже введённых вручную. |
| **Анализ покрытия LO** | Показывает, какими дисциплинами подтверждается каждый результат обучения. План не меняет. |
| **Проанализировать с AI** | Даёт диагностические рекомендации. Автоматически план не переписывает. |
| **Создать bridge-модули** | Предлагает новые междисциплинарные модули для непокрытых LO. |
| **Подтвердить и добавить дисциплину** | Переносит одобренный модуль в репозиторий. |
| **Построить варианты** | Пересчитывает варианты A/B/C и заменяет ими предыдущие варианты этой версии. |
| **Применить все улучшения** | Добавляет недостающие элементы международного чек-листа и перестраивает A/B/C. |
| **Сделать активным** | Утверждает выбранный вариант, переводит проект из статуса «Черновик» в «Активен». |

## Как система работает целиком

`Название и области → цель → LO → ограничения → анализ базы дисциплин → граф связей → варианты A/B/C → проверка качества → утверждение активного плана`.

- A стремится максимизировать покрытие LO.
- B старается использовать меньше новых дисциплин.
- C ищет сбалансированный вариант с меньшим количеством конфликтов и повторов.
- Перед утверждением система проверяет кредиты, нагрузку семестров, пререквизиты, предметную релевантность, покрытие LO и международный чек-лист.
- Активным может быть только один вариант плана данной версии.

## Итоговая оценка системы

Текущая оценка готовности: **8,5 из 10 для демонстрации и опытной эксплуатации**.

Сильные стороны:

- полный понятный путь от идеи программы до активного плана;
- автоматические подсказки целей и LO с сохранением экспертного контроля;
- три действительно различающихся варианта;
- проверка ограничений и международный чек-лист;
- объяснимые связи LO с дисциплинами и журналируемые действия;
- простой локальный запуск без тяжёлой инфраструктуры.

Почему пока не 10 из 10:

- для строгого воспроизведения диссертационной инфраструктуры нужны PostgreSQL/pgvector и SBERT;
- для численного сравнения с GNN/LSTM нужны исходные веса, признаки и датасет;
- перед промышленным внедрением необходимы внешняя экспертная апробация, нагрузочное тестирование, резервное копирование и настройка прав пользователей.

Иными словами: система уже является сильным работающим прототипом и подходит для защиты и демонстрации, но окончательное промышленное и научно-экспериментальное подтверждение требует внешней инфраструктуры и данных.

## Продолжительность программы и распределение кредитов

В мастере указывается **продолжительность в годах**, а не количество семестров:

- 1 год = 2 семестра = рекомендуемые 60 кредитов;
- 2 года = 4 семестра = рекомендуемые 120 кредитов;
- 4 года = 8 семестров = рекомендуемые 240 кредитов.

При изменении количества лет мастер автоматически пересчитывает семестры и рекомендуемый общий объём кредитов. Общий объём при необходимости можно затем изменить вручную.

Планировщик резервирует место для вводных дисциплин, соблюдает порядок пререквизитов и распределяет остальные дисциплины по семестрам. Допустимая нагрузка при настройке 30 кредитов составляет 27–33 кредита. План с выходом за этот диапазон отмечается как недопустимый и не должен утверждаться без перестройки.

Проверка программы «Цифровая аналитика и искусственный интеллект в государственном секторе» после исправления:

- срок обучения — 4 года, 8 семестров;
- каждый вариант A/B/C содержит ровно 240 кредитов;
- нагрузка по семестрам находится в диапазоне 27–32 кредита;
- нарушений нагрузки и пререквизитов нет;
- все варианты допустимы, международный чек-лист — 100%.

# Уникальность дисциплин

Генератор считает дисциплины с одинаковым названием одной дисциплиной, даже если они импортированы в репозиторий под разными идентификаторами. Дубликаты не включаются в учебный план повторно. Если уникальных дисциплин недостаточно для заданного количества кредитов, система создаёт отдельные bridge-модули с уникальными названиями и объёмом не более 7 кредитов, сохраняя связи пререквизитов.
# Обновлённый интерфейс

Главная страница оформлена как спокойное рабочее пространство: крупный заголовок показывает текущий контекст, карточки — количество программ и их состояние, а таблица проектов содержит основные действия без скрытых меню. Цвет используется функционально: синий обозначает основное действие, зелёный — активное состояние, красный — удаление.

Интерфейс адаптируется к ширине окна. На небольшом экране карточки и действия перестраиваются в одну колонку, при этом все функции остаются доступны.

Единый стиль теперь используется в конструкторе программы, анализе покрытия РО, планировщике и графе пререквизитов. Граф намеренно открывается в тёмном режиме: слева показаны дисциплины семестра, в центре — связи, справа — приобретаемые результаты и доступные следующие дисциплины.

Первый запуск может занять до двух минут: система загружает локальную языковую модель. Окно запуска в это время закрывать не нужно.

В планировщике под каждым семестром отображаются подтверждённые результаты программы. Наведите указатель на код `LO`: появятся полный текст результата, дисциплины-подтверждения и сила связи. Если доказательств нет, система показывает явное пояснение вместо пустого поля.

Переводы дисциплин хранятся отдельно от исходной базы. Машинный перевод получает статус черновика и не показывается пользователям до терминологической проверки — это защищает учебный план от буквальных, но неверных переводов академических терминов.

Подпись «Перевод ИИ, прошёл автоматическую проверку» означает, что трёхъязычное название не найдено в ЕПВО и было создано локальной моделью, проверено правилами и терминологическим словарём. Исходное название дисциплины при этом не изменяется.

При создании программы обязательны уровень образования, область, направление подготовки, группа ОП, тип программы и язык обучения. Срок в годах автоматически задаёт число семестров и рекомендуемую сумму кредитов. Кнопка продолжения остаётся недоступной, пока обязательные поля, LO и ограничения не заполнены.

Во время построения вариантов кнопка показывает процент выполнения. Повторный запуск блокируется; при ошибке старый активный план сохраняется.

Кнопка «Сравнить с ЕПВО» открывает эталонную выборку для направления или группы ОП. Таблица показывает типовые дисциплины, рекомендуемые кредиты и семестр, распространённость по программам ЕПВО и наличие дисциплины в текущем плане. Данные этого экрана являются справочными и сами план не изменяют.

При выборе дисциплины на графе показываются связанные LO, процент прогноза ИИ и причина включения в план. Кнопки «Подтвердить», «Слабая связь» и «Неверная» сохраняют экспертную оценку отдельно от исходного прогноза для последующего обучения и benchmark.

Раздел «Данные и качество модели» на главной странице показывает паспорт датасета, train/validation/test, seed, контрольные SHA-256 и результаты сравнения моделей. Пустое значение ranking-метрики означает «ещё не измерено», а не нулевое качество.
# Как читать карточку дисциплины в плане

- **Название дисциплины** всегда показывается отдельной строкой; внутренний ID больше не выводится как часть названия.
- **Цикл**: `ООД` — общеобразовательные дисциплины, `БД` — базовые, `ПД` — профилирующие. Для ГОСО цикл берётся из нормативной записи; для остальных дисциплин, если ЕПВО не передал цикл, интерфейс честно помечает его как расчёт системы.
- **Компонент** показывается отдельно: обязательный, вузовский, по выбору, практика, НИР или итоговая аттестация.
- Дисциплины с кодом `GOSO-KZ-*` защищены от удаления, списка сомнительных дисциплин и подбора замены **только если на первом шаге выбрано «ГОСО РК»**. Для международной юрисдикции эта защита не действует, и такие дисциплины проходят обычный аудит релевантности.

В блоке «Почему выбрана?» проценты относятся к одной связи `дисциплина → LO`:

- **ИИ** — оценка смысловой связи моделью по названию, описанию дисциплины и тексту LO;
- **ЕПВО** — поддержка той же связи в исторических экспертных данных ЕПВО;
- **итог** — наиболее надёжная подтверждённая оценка. ИИ и ЕПВО не складываются.

Например, `LO3 · итог 63% · ИИ 63% · ЕПВО 21%` означает: система уверена в связи этой дисциплины именно с LO3 на 63%; модель дала 63%, а исторические данные ЕПВО дают дополнительное, но более слабое подтверждение 21%.
